# Database

Localink uses Drizzle ORM with a locally stored SQLite database. Database code lives under `src/lib/drizzle`, with schema in `schema.ts` and generated SQL migrations in `src/lib/drizzle/migrations`.

## Data Mode

Set `LOCALINK_DATA_MODE` in `.env`:

```env
LOCALINK_DATA_MODE=dev
```

Valid values are `dev` and `prod`. If the variable is omitted, Localink defaults to `dev`.

Database files are stored under the mode-specific app data folder:

- `data/dev/localink.sqlite`
- `data/prod/localink.sqlite`

The app creates the mode folder when it opens the database. `data/` contents are ignored by git because they contain local user data.

## Schema

The writing model has four content tables, one generated media metadata table, and one app metadata table:

- `stories`: `id`, `name`, `description`, `characters`, `locations`, `style`, `created_at`, `updated_at`
- `chapters`: `id`, `story_id`, `name`, `position`, `content`, `updated_at`
- `story_chats`: `id`, `story_id`, `title`, `created_at`, `updated_at`
- `story_chat_messages`: `id`, `story_id`, `chat_id`, `role`, `is_visible`, `position`, `content`, `generation_id`, `created_at`, `updated_at`
- `generated_images`: `id`, `provider`, `provider_response_id`, `prompt`, `style_preset`, `style_prompt`, `model`, `aspect_ratio`, `image_size`, `width`, `height`, `mime_type`, `file_relative_path`, `file_size`, `created_at`
- `metadata`: `key`, `value`, `updated_at`

`chapters.story_id` references `stories.id` with cascading delete behavior. `chapters.position` stores the chapter order within a story, and `chapters_story_position_idx` supports loading chapters by story in order.

`story_chats` stores story-scoped planning chats. Chat rows belong to a story and cascade on story delete. The `story_chats_story_updated_idx` index supports loading recent chats for a story history picker.

`story_chat_messages` stores ordered chat messages. Visible messages use `role` values of `user` or `assistant`; hidden style, character, and location context snapshots use `role = 'system'` with `is_visible = 0` and intentionally exclude story description, manuscript text, and outline content. Each prepared generation stores a hidden context snapshot row with a `generation_id`, and the saved assistant reply stores the same `generation_id` for traceability. `story_id` and `chat_id` both cascade on delete. `story_chat_messages_chat_position_unique` is a UNIQUE index on `(chat_id, position)` that supports loading visible chat history in order and prevents duplicate positions; `story_chat_messages_generation_idx` supports validating prepared generations before streaming or saving output.

`stories.characters` stores a JSON array of `{ id, name, description }` objects for story-level character context. `stories.locations` stores the same shape for story-level location context. Character and location IDs are hidden from users and generated by the server when missing. `stories.style` stores story-level prose/style guidance as text.

`metadata` stores global app settings and small local bookkeeping values. The `ai.systemInstructions` key stores the user-configured global AI system instructions. Missing or blank values mean LocalInk uses only its built-in system prompts. The setting is global to the local app, not scoped to a story.

`generated_images` stores metadata for images generated through the configured image provider. The image bytes are stored as local files under `data/<mode>/generated-images/`, and `file_relative_path` points to that mode-specific data directory. The `generated_images_created_at_idx` index supports newest-first gallery loads. See `docs/ai-image-generation.md` for provider flow, routes, and generated-image logging rules.

`stories.created_at`, `stories.updated_at`, `chapters.updated_at`, `story_chats.created_at`, `story_chats.updated_at`, `story_chat_messages.created_at`, and `story_chat_messages.updated_at` default to the current UTC timestamp on insert. SQLite triggers refresh the story and chapter `updated_at` fields automatically on row updates when the write does not explicitly change `updated_at`; chat actions write chat and message timestamps explicitly.

## Migrations

Migrations are generated from the TypeScript schema:

```bash
bun run db:generate -- --name=<migration-name>
```

Migrations can be applied manually:

```bash
bun run db:migrate
```

They also run automatically when the Next server starts. `src/instrumentation.ts` calls the migration runner only in the Node.js runtime, before the server starts handling requests. Drizzle tracks applied migrations in SQLite with its `__drizzle_migrations` table, so repeated starts are no-ops unless new migration files exist.

Migration `0009_rename-metadata-table` renames the original `localink_metadata` table to `metadata` with `ALTER TABLE`, preserving existing local key/value rows.

Migration `0010_remove-indexing` drops the `chunks` table, removes `chapters.indexed_hash`, `chapters.indexed_at`, and `chapters.summary`, and replaces the non-unique `story_chat_messages_chat_position_idx` with the unique index `story_chat_messages_chat_position_unique` on `(chat_id, position)`.

Migration `0001_story-locations` adds `stories.locations` as a JSON text column with a default empty array for existing local databases.
